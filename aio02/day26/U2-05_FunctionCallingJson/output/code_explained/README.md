# 수업 코드 그림 설명

`index.html`을 열면 8장의 이미지를 순서대로 볼 수 있습니다. `00_all_pages.png`는 전체 미리보기입니다.

1. `01_overview.png` — 전체 학습 지도와 역할 비유
2. `02_function_call_roundtrip.png` — main01: 배송비 함수 호출 왕복
3. `03_sdk_vs_langchain.png` — main02: SDK와 LangChain 비교
4. `04_json_schema.png` — main03: 명확한 스키마와 단위 변환
5. `05_multiple_tools_and_providers.png` — main04·07: 여러 도구와 제공자별 형식
6. `06_pydantic_validation.png` — main05: 입력 검증과 할인 계산
7. `07_error_feedback.png` — main06: 오류 피드백과 재시도
8. `08_refund_agent.png` — main08: 주문 조회·환불 예상 금액·추적·평가

## 분석에서 확인한 내용

- 각 파일은 독립 실행 예제이며 파일끼리 import하거나 순서대로 자동 실행하지 않습니다.
- AI는 도구 이름과 인자를 요청합니다. 프로그램이 함수를 실행하고 결과를 모델에게 반환해야 대화가 완성됩니다.
- main01·02·04는 모델을 1차 호출하고, 도구 요청이 있으면 실행 후 2차 호출합니다. 범용 무한 반복 에이전트가 아닙니다.
- main03은 두 스키마로 추출된 인자만 출력합니다. 예상 비용 2.40달러는 코드의 `estimate_cloud_cost('small', 48)`로 별도 검증한 값입니다. 리전별 실제 서비스 요금이 아닙니다.
- main04는 여러 호출 요청을 허용하지만 로컬 도구는 for문으로 순차 실행합니다. 기본 질문은 정수기의 동작원리이며, 가격·환율 질문은 주석에 있습니다. 환율은 고정 예제 데이터입니다.
- main05는 AI 없이 스키마와 도구 검증을 보여줍니다. 기본 `.invoke()`의 반환값을 출력하지 않습니다. `ceil` 분기는 계산 결과가 정수이면 `0`을 반환하는 버그가 있습니다. 원본은 수정하지 않았습니다. 수정한다면 `math.ceil(raw)`와 같은 올림 연산이 적절합니다.
- main06의 0.8 할인 요청에 모델이 어떤 인자를 생성하고 어떤 최종 안내를 하는지는 실제 응답에 따라 달라집니다. 임의로 0.5로 바꾸도록 강제한 구현은 없습니다. 최대 5회 모델 호출 제한입니다.
- main07은 제공자별 호출 요청 형식만 확인합니다. 실제 배송 권역 함수 실행 및 결과 반환 단계는 없습니다. 모델명이나 SDK의 현재 사용 가능 여부는 이번 분석에서 검증하지 않았습니다.
- main08은 환불 예상 금액만 계산하며 실제 환불 처리는 없습니다. 최대 6회 모델 호출 제한입니다. 태그와 시스템 지시는 방어 의도를 표현하며 완전한 방어를 보장하지 않습니다. 평가 함수는 특정 문자열을 검사하며 정답 금액 전체를 검사하지 않습니다. LangSmith 데이터셋 평가를 실행하려면 해당 연결 설정과 데이터셋이 필요합니다.

## 제작 및 검증

이미지는 Pillow와 Windows 맑은 고딕으로 직접 렌더링했습니다. AI 이미지 생성 도구와 유료 이미지 API는 사용하지 않았습니다. 재생성은 번들 Python에서 `build_images.py`를 실행하면 됩니다.

원본 코드를 AST로 읽어 API 연결을 만들지 않고 순수 함수 본문만 분리 실행해 배송비, 비용, 할인, 올림 분기의 버그, 환불 두 건, 배송 권역을 확인했습니다. 카드별 텍스트 영역 초과 여부도 검사했습니다. `.env`의 내용은 읽지 않았으며 외부 AI 및 LangSmith 호출도 실행하지 않았습니다.
