# day24 소스코드 기능과 핵심 개념 정리

`day24`의 두 실습을 기능별로 정리한 학습 자료입니다. 구조화 출력 실습은 AI 결과의 형식과 원본 일치를 검증하고, 에이전트 오케스트레이션 실습은 Gemini의 의도 분석과 DB 조회를 OpenAI의 최종 답변 생성으로 연결합니다.

은행 데이터 변환과 SQLite 결과는 로컬 실행으로 확인한 예시입니다. SQLite 수치는 기본 시드로 새로 생성한 가상 DB 기준입니다. AI의 의도 분석과 자연어 답변은 설명용 예시이며 실제 모델 응답은 아닙니다.

## 4 구조화 출력 실습의 목적

구조화 출력은 프로그램이 처리하기 쉽도록 필드와 타입을 정해 결과를 받는 방식입니다.

실제 은행 CSV 첫 행에서 선택한 입력은 다음과 같습니다.

```python
row = {
    "duration": "79",
    "campaign": "1",
    "poutcome": "unknown"
}
```

목표 JSON은 다음과 같습니다.

```json
{
  "duration_s": 79,
  "contacts": 1,
  "previous_result": null
}
```

변환 규칙은 `duration → duration_s`, `campaign → contacts`, `poutcome → previous_result`, `unknown → null`입니다.

```text
원본 CSV 또는 JSON
  → 필요한 필드 선택
  → AI 변환 요청
  → Pydantic 형식 검증
  → 원본으로 만든 정답과 비교
  → JSON과 HTML 보고서 저장
```

| 실행 모드 | 기능 | AI 호출 |
|---|---|---|
| `inspect` | 원본 확인 | 없음 |
| `schema` | JSON Schema 확인 | 없음 |
| `diagnose` | 검증 성공·실패 사례 실험 | 없음 |
| `plain` | 프롬프트로 JSON 요청 | 있음 |
| `strict` | API 설정에도 JSON Schema 전달 | 있음 |
| `chain` | LangChain 구조화 출력 | 있음, OpenAI 전용 |

## 5 Pydantic 모델 선언과 검증

```python
from typing import Literal
from pydantic import BaseModel, ConfigDict

class Contract(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)

class Contact(Contract):
    duration_s: int
    contacts: int
    previous_result: Literal["success", "failure", "other"] | None
```

| 문법 | 기능 |
|---|---|
| `class Contact(Contract)` | 부모의 검증 설정을 상속 |
| `duration_s: int` | 정수 필드 선언 |
| `Literal[...]` | 허용하는 특정 값 명시 |
| `... \| None` | `None`도 허용 |
| `extra="forbid"` | 추가 필드 금지 |
| `strict=True` | 타입을 엄격하게 검사 |

`Literal`은 허용값을 표현하는 타입 힌트입니다. 일반 파이썬은 타입 힌트만으로 값을 검사하지 않지만 Pydantic은 이를 읽어 실행 중 검증합니다.

`ConfigDict`는 `TypedDict` 기반 클래스이며 호출 결과는 일반 딕셔너리입니다.

```python
config = ConfigDict(extra="forbid", strict=True)
print(type(config))
# <class 'dict'>
```

세 필드를 넣어 객체를 생성합니다.

```python
obj = Contact(duration_s=79, contacts=1, previous_result=None)
print(obj)
# duration_s=79 contacts=1 previous_result=None
```

`previous_result`는 `None`을 허용하지만 기본값이 없으므로 키 자체는 필수입니다.

```python
Contact(duration_s=79, contacts=1)
# ValidationError: previous_result 누락

Contact(duration_s="79", contacts=1, previous_result=None)
# ValidationError: duration_s 타입 오류
```

상품용 `Product`는 필수 필드 `title: str`, `category: str`, `price: float`를 선언합니다.

### 기억할 메서드 다섯 가지

| 문법 | 필수 입력 | 반환값 |
|---|---|---|
| `Contact.model_validate(data)` | 파이썬 객체, 여기서는 딕셔너리 | `Contact` |
| `Contact.model_validate_json(text)` | JSON 문자열 또는 바이트 | `Contact` |
| `Contact.model_json_schema()` | 추가 필수 인자 없음 | 형식 설명서 `dict` |
| `obj.model_dump()` | 추가 필수 인자 없음 | 데이터 `dict` |
| `obj.model_dump_json()` | 추가 필수 인자 없음 | JSON `str` |

```python
obj.model_dump()
# {'duration_s': 79, 'contacts': 1, 'previous_result': None}

obj.model_dump_json()
# '{"duration_s":79,"contacts":1,"previous_result":null}'
```

## 6 JSON과 JSON Schema와 파이썬 객체

JSON은 데이터를 표현하는 텍스트 형식이고, JSON Schema는 그 데이터의 구조·타입·필수 필드 규칙입니다.

실제 데이터:

```json
{"duration_s": 79}
```

설명용 스키마:

```json
{
  "type": "object",
  "properties": {
    "duration_s": {"type": "integer"}
  },
  "required": ["duration_s"],
  "additionalProperties": false
}
```

이 규칙은 정수인지 검사하지만 원본 값이 79인지까지 검사하지는 않습니다. 80도 정수이기 때문입니다. 따라서 형식 검증과 원본 대조가 모두 필요합니다.

```python
import json

data = {"title": "가방", "available": True, "previous_result": None}
text = json.dumps(data, ensure_ascii=False)
print(text)
# {"title": "가방", "available": true, "previous_result": null}

print(type(text))
# <class 'str'>

restored = json.loads(text)
print(restored["title"])
# 가방
```

| 함수 | 필수 입력 | 기능 |
|---|---|---|
| `json.dumps(data)` | 파이썬 객체 | JSON 문자열 생성 |
| `json.loads(text)` | JSON 문자열·바이트 | 파이썬 객체로 복원 |
| `json.load(stream)` | 읽을 수 있는 파일·응답 객체 | JSON을 읽어 파이썬 객체로 변환 |

`ensure_ascii=False`는 한글을 그대로 표현합니다. `dumps()` 자체는 저장이나 전송을 하지 않습니다.

JSON의 `{...}`는 `dict`, `[...]`는 `list`, `null`은 `None`, `true`와 `false`는 `bool`로 변환됩니다. 상품 파일에서는 딕셔너리들이 담긴 리스트를 기대합니다.

## 7 원본 읽기와 정답 생성

| 함수 | 필수 인자 | 기능 | 반환값 |
|---|---|---|---|
| `read_rows(dataset)` | 데이터셋 이름 | CSV·JSON 원본 읽기 | `list` |
| `project(dataset, source)` | 데이터셋, 원본 한 행 | 필요한 필드만 선택 | `dict` |
| `reference(dataset, row)` | 데이터셋, 선택한 데이터 | 코드로 정답 생성 | `Contact` 또는 `Product` |
| `diagnose(row)` | 은행 데이터 한 행 | 일부러 틀린 데이터로 검사 | 결과 `dict` |

```python
with path.open(encoding="utf-8-sig", newline="") as stream:
    rows = list(csv.DictReader(stream, delimiter=";"))
```

- `path.open()`은 파일 객체를 만들고, `with`는 사용 후 파일을 닫습니다.
- `utf-8-sig`는 UTF-8 파일 맨 앞의 BOM이 있으면 제거합니다. BOM은 파일 처음에 붙을 수 있는 특수 바이트 표시입니다.
- `newline=""`는 줄바꿈을 없애는 설정이 아니라 원래 문자를 유지하여 CSV 모듈이 처리하도록 하는 설정입니다.
- `DictReader`는 `fieldnames`를 생략하면 첫 행을 키 이름으로 사용합니다.
- `delimiter=";"`는 세미콜론으로 필드를 구분합니다.
- CSV에서 읽은 위 값은 문자열입니다.

필요한 필드를 고르는 문법은 딕셔너리 컴프리헨션입니다.

```python
keys = ("duration", "campaign", "poutcome")
selected = {key: source[key] for key in keys}
```

실제 은행 데이터의 결과:

```python
rows = read_rows("bank")
row = project("bank", rows[0])
print(row)
# {'duration': '79', 'campaign': '1', 'poutcome': 'unknown'}

print(reference("bank", row).model_dump())
# {'duration_s': 79, 'contacts': 1, 'previous_result': None}
```

`reference()`는 AI 없이 `int("79")`, `int("1")`과 조건문으로 정답을 만듭니다.

`diagnose(row)`의 실제 결과:

| 입력 사례 | 결과 |
|---|---|
| 정상 데이터 | 통과 |
| 필수 키 삭제 | `missing` |
| 정수 대신 문자열 | `int_type` |
| 허용 목록 밖의 값 | `literal_error` |
| 추가 키 | `extra_forbidden` |
| 정수이지만 원본과 다른 값 | 형식 통과 / 원본 불일치 |

상품 데이터는 로컬 파일이 없으면 다운로드하고, 각 상품을 검증한 뒤 임시 파일에서 최종 파일로 옮겨 저장합니다. 은행 데이터는 로컬 CSV를 읽습니다.

## 8 AI 호출과 결과 저장

### 직접 HTTP 요청

```python
req = Request(
    url,
    data=json.dumps(body).encode(),
    headers={**headers, "Content-Type": "application/json"}
)

with urlopen(req, timeout=60) as response:
    data = json.load(response)
```

| 표현식 | 기능과 결과 |
|---|---|
| `Request(url, ...)` | URL이 필수 입력. 요청 객체 생성 |
| `json.dumps(body)` | 딕셔너리를 JSON 문자열로 변환 |
| `.encode()` | 문자열을 UTF-8 바이트로 변환 |
| `urlopen(req, ...)` | URL 또는 요청 객체를 받아 실제 전송 |
| `json.load(response)` | 응답 JSON을 파이썬 객체로 변환 |

`Request()` 생성만으로 전송하지 않으며 `urlopen()`에서 전송합니다. `data`를 지정한 이 요청은 기본적으로 POST입니다.

딕셔너리 펼치기는 새 딕셔너리를 만듭니다.

```python
headers = {"Authorization": "Bearer EXAMPLE_KEY"}
new_headers = {**headers, "Content-Type": "application/json"}

print(new_headers)
# {'Authorization': 'Bearer EXAMPLE_KEY', 'Content-Type': 'application/json'}

print(headers)
# {'Authorization': 'Bearer EXAMPLE_KEY'}
```

같은 키가 있으면 새 딕셔너리 안에서 뒤의 값이 우선합니다. 원래 `headers`는 변경되지 않습니다.

### LangChain 구조화 출력

```python
llm = ChatOpenAI(model=model, api_key=key, max_retries=0, timeout=60)
chain = llm.with_structured_output(
    Contact,
    method="json_schema",
    strict=True,
    include_raw=True
)
reply = chain.invoke(prompt)
```

`ChatOpenAI()`는 호출 설정 객체를 만들고, `with_structured_output()`은 결과 모델을 지정하며, `invoke(prompt)`가 실제 모델 호출을 수행합니다.

정상 응답의 구조 예시:

```python
{
    "raw": AIMessage(...),
    "parsed": Contact(duration_s=79, contacts=1, previous_result=None),
    "parsing_error": None
}
```

### 생성 결과 검증

```python
parsed = Contact.model_validate_json(raw)
if parsed != reference("bank", row):
    raise ValueError("원본 대조 실패")
```

API 거절, 중단, 빈 응답도 확인합니다. Groq·Gemini의 HTTP 429는 OpenAI로 한 번 전환합니다.

| 함수 | 필수 인자 | 결과 |
|---|---|---|
| `call_api(provider, prompt, schema_type, mode, report)` | 서비스·프롬프트·모델 클래스·모드·기록 | 생성 문자열 |
| `generate(provider, mode, dataset, row, report)` | 서비스·모드·데이터셋·행·기록 | `report` 수정, 반환값 `None` |
| `write_report(report)` | 실행 기록 | JSON·HTML 저장과 화면 출력, 반환값 `None` |

`call_api()`에 전달하는 `report`에는 `attempts` 리스트가 준비되어 있어야 합니다.

보고서는 `runs/실행시각.json`, `runs/실행시각.html`로 저장합니다. 원본 SHA-256 해시는 파일 식별용이고, `html.escape()`는 결과가 HTML 태그 대신 문자로 표시되도록 합니다.

```python
parser = argparse.ArgumentParser()
```


해석 후에는 `args.mode == "strict"`, `args.row == 1`처럼 속성으로 접근합니다.

```python
if __name__ == "__main__":
    raise SystemExit(main())
```

직접 실행하면 `__name__`은 `"__main__"`입니다. 일반적으로 `import main`으로 가져오면 `"main"`이며 두 문자열은 다릅니다.

파일은 import·전역 변수·클래스·함수 정의를 위에서 아래로 처리한 뒤 진입점에 도달합니다. 함수 본문은 호출할 때 실행됩니다.

```python
code = main()              # 먼저 main 실행
exit_exception = SystemExit(code)  # 종료 예외 객체 생성
raise exit_exception       # 예외를 발생시켜 종료
```

`SystemExit`은 예외 클래스이며 객체 생성만으로 종료하지 않습니다. 잡히지 않은 `SystemExit`이 발생하면 종료합니다. 종료 코드 0은 성공, 일반적으로 0 이외는 실패입니다.

구조화 출력 실습은 `.env`를 자동으로 읽지 않고 `os.getenv()`로 현재 환경변수를 읽습니다.

## 11 에이전트 오케스트레이션의 목적

오케스트레이션은 여러 작업과 모델의 실행 순서, 데이터 전달, 실패 처리를 조율하는 것입니다.

```text
사용자 질문
  → Gemini 의도 분석
  → 원문 식별자와 기간 검증
  → 필요한 경우 Gemini가 SQL 도구 호출 요청
  → Python이 SQLite 조회
  → 필요하면 추가 조회
  → 실제 결과를 OpenAI에 전달
  → 최종 답변
```

Gemini는 도구 호출을 요청하고 실제 SQL은 Python이 실행합니다. OpenAI는 조회 결과를 받아 설명합니다. 이 실습에는 LangChain이나 LangGraph가 없으며 직접 만든 Python 코드가 흐름을 제어합니다.

| 상황 | 처리 |
|---|---|
| 모호한 질문 | 추가 확인 질문 반환 |
| 지원하지 않는 수정·삭제 | 미지원 사유 반환 |
| 일반 지식 질문 | DB 조회 생략 |
| DB 조회 실패 | OpenAI 답변 생성 중단 |
| 최종 답변 생성 실패 | 조회 기록 보존 |

## 12 Settings와 AgentClient

```python
@dataclass(frozen=True)
class Settings:
    request_timeout_seconds: float
    max_tool_rounds: int

settings = Settings(request_timeout_seconds=60, max_tool_rounds=3)
```

`@dataclass`는 필드 선언을 바탕으로 초기화 메서드 등을 만들어 주는 데코레이터입니다. `frozen=True`는 필드 재대입을 막습니다.

```python
settings.max_tool_rounds = 5
# FrozenInstanceError
```

dataclass는 타입 힌트에 맞는 값인지 자동 검증하지 않습니다. 이 코드에서는 `load_settings()`가 숫자와 범위를 검증합니다.

```python
@dataclass(frozen=True)
class AgentClient:
    name: str
    model: str
    api_kind: ApiKind
    client: OpenAI = field(repr=False)
```

| 필드 | 의미 |
|---|---|
| `name` | `gemini` 또는 `openai` |
| `model` | 모델명 |
| `api_kind` | `responses` 또는 `chat_completions` |
| `client` | SDK HTTP 클라이언트 |

`field(repr=False)`는 객체 표현에서 `client`를 제외합니다. 내부 객체까지 모두 불변으로 만드는 설정은 아닙니다.

```python
agent.generate(prompt, instructions=None, response_schema=None)
```

`prompt`가 필수이고 선택 설정은 이름을 붙여 전달합니다. 반환값은 `str`입니다.

```python
text = agent.generate(
    "법인카드가 무엇인지 설명해줘",
    instructions="한국어로 짧게 답하세요."
)
```

내부에서는 두 API 중 하나를 호출합니다.

```python
client.responses.create(
    model=model,
    input=prompt,
    instructions=instructions
)
```

```python
client.chat.completions.create(
    model=model,
    messages=[
        {"role": "system", "content": instructions},
        {"role": "user", "content": prompt}
    ]
)
```

`OpenAI(...)`는 클라이언트를 만들고 `.create(...)`가 실제 요청을 보냅니다. 기본 파이프라인은 Gemini에 Chat Completions 호환 API, OpenAI에 Responses API를 사용합니다. SDK가 같아도 모델 제공사가 같은 것은 아닙니다.

| 함수 | 필수 인자 | 반환값 |
|---|---|---|
| `parse_reference_date(value)` | 날짜 문자열 | `date` |

## 15 상대 기간 계산

```python
parsed = date.fromisoformat("2026-11-22")
parsed.isoformat()
# '2026-11-22'
```

`parse_reference_date()`는 유효한 날짜인지와 정확한 `YYYY-MM-DD` 표기를 검사합니다.

```python
parse_reference_date("2026-11-31")
# ValueError
```

이번 달 범위 계산:

```python
month_start = reference.replace(day=1)
last_day = calendar.monthrange(reference.year, reference.month)[1]
month_end = reference.replace(day=last_day)
```

`calendar.monthrange(year, month)`는 `(그달 1일의 요일, 그달의 날짜 수)`를 반환합니다.

기준일 `2026-11-22`에 대한 규칙 예시:

```python
relative_period_rules(date(2026, 11, 22))["이번달"]
# ['2026-11-01', '2026-11-30']

relative_period_rules(date(2026, 11, 22))["지난달"]
# ['2026-10-01', '2026-10-31']
```

이번 달은 월말까지이고, `오늘까지/현재까지/지금까지`가 명시되면 기준일까지 제한합니다. `최근`처럼 모호한 표현은 임의 기간으로 만들지 않고 확인 질문을 요청합니다.

Python의 결정적 보정은 등록된 상대 기간 표현에 적용됩니다. 특정 연월을 명시한 표현은 Gemini가 해석하고 Python이 날짜의 유효성과 순서 등을 검사합니다.

## 17 SQL 조회 문법과 실제 결과

```python
query_database(sql, parameters=None, row_limit=200)
```

필수 인자는 SQL 문자열 하나입니다. `parameters`는 값의 리스트이며, `row_limit`은 1~200 정수입니다.

```python
result = query_database(
    """
    SELECT employee_id, name, department, corporate_card_id
    FROM employees
    WHERE employee_id=?
    """,
    ["E001"]
)
```

기본 시드로 새로 생성한 DB의 실제 결과:

```python
result["data"]["rows"]
# [{'employee_id': 'E001', 'name': '김가온',
#   'department': '개발팀', 'corporate_card_id': 'CARD-1001'}]
```

11월 사용액 조회:

```python
result = query_database(
    """
    SELECT COUNT(*) AS count, SUM(amount_krw) AS total_krw
    FROM card_transactions
    WHERE corporate_card_id=?
      AND used_at BETWEEN ? AND ?
    """,
    ["CARD-1001", "2026-11-01", "2026-11-30"]
)
print(result["data"]["rows"])
# [{'count': 3, 'total_krw': 423500}]
```

전체 기간의 같은 카드 거래는 10건, 합계 2,277,100원입니다. 기존 DB가 수정되었거나 다른 시드로 생성되었다면 값은 달라집니다.

| SQL 문법 | 기능 |
|---|---|
| `SELECT` | 조회할 컬럼 지정 |
| `WHERE` | 조건 지정 |
| `JOIN` | 테이블 연결 |
| `COUNT(*)` | 건수 계산 |
| `SUM(amount_krw)` | 합계 계산 |
| `AS total_krw` | 출력 컬럼 별칭 |
| `BETWEEN ? AND ?` | 양 끝을 포함하는 범위 |
| `GROUP BY` | 그룹별 집계 |
| `ORDER BY` | 정렬 |

파라미터 바인딩은 SQL과 값을 분리하는 방식입니다.

```python
cursor = connection.execute(sql, parameters)
rows = cursor.fetchmany(row_limit + 1)
```

한 행을 더 가져와 상한 초과 여부를 확인합니다. 반환 구조는 다음과 같습니다.

```python
{
    "status": "success",
    "data": {
        "columns": ["count", "total_krw"],
        "rows": [{"count": 3, "total_krw": 423500}],
        "returned_count": 1,
        "truncated": False,
        "row_limit": 200
    },
    "error": None
}
```

조회는 읽기 전용 연결과 SQLite authorizer를 사용합니다. 허용된 두 테이블의 읽기를 허용하고 변경·삭제·외부 DB 연결 등을 차단하며, 행 수와 실행 시간 예산을 제한합니다.

`truncated=True`이면 전체 목록이 아닙니다. 전체 합계는 잘린 목록을 더하지 말고 SQL의 `SUM()`으로 계산해야 합니다.

| 구성 | 역할 |

| `DATABASE_SCHEMA` | 모델에 전달할 테이블·컬럼·연결 관계 설명 |
| `TOOL_DEFINITIONS` | 공개 도구의 이름·설명·입력 JSON Schema |
| `TOOL_REGISTRY` | 도구 이름과 실제 함수 연결 |
| `execute_tool()` | 등록 여부와 인자를 검사하고 함수 실행 |

```python
TOOL_REGISTRY = {"query_database": query_database}

result = execute_tool(
    "query_database",
    '{"sql": "SELECT COUNT(*) AS count FROM employees"}'
)
print(result["data"]["rows"])
# [{'count': 100}]
```

필수 인자는 도구 이름 문자열과 JSON 인자 문자열입니다.

```python
args = json.loads(arguments)
inspect.signature(TOOL_REGISTRY[name]).bind(**args)
return TOOL_REGISTRY[name](**args)
```

1. JSON을 딕셔너리로 바꿉니다.
2. 함수가 받는 인자 이름과 개수가 맞는지 검사합니다.
3. 인자를 키워드로 펼쳐 등록 함수를 실행합니다.

```python
args = {"sql": "SELECT COUNT(*) AS count FROM employees"}
query_database(**args)
# query_database(sql="SELECT COUNT(*) AS count FROM employees")와 같음
```

`inspect.signature(...).bind()`는 함수 호출 형태를 검사하며 값의 타입까지 모두 검증하지는 않습니다. SQL·바인딩 값·행 상한의 실제 타입 검사는 `query_database()`가 수행합니다.

모델 출력은 `eval()`로 실행하지 않습니다. JSON으로 읽고 등록된 함수만 호출합니다. 선택 인자의 `null`은 제거하여 파이썬 기본값을 사용합니다.

## 19 도구 호출 반복과 최종 답변

```python
agent.run_with_tools(
    context,
    instructions=...,
    max_rounds=3,
    trace=trace,
    require_query=True
)
```

필수 입력은 `context`, `instructions`, `max_rounds`, `trace`입니다. 반환값은 완료 문자열이고, 실행 기록은 전달받은 `trace` 리스트에 추가합니다.

```text
모델에 도구 명세 전달
  → 모델이 도구 이름과 인자 반환
  → execute_tool 실행
  → 결과를 호출 ID와 함께 모델에 전달
  → 추가 조회 또는 완료 응답
```

호출 ID는 어떤 도구 요청에 대한 결과인지 연결하는 식별자입니다.

```python
# Chat Completions 방식
{"role": "tool", "tool_call_id": call.id, "content": output}

# Responses 방식
{"type": "function_call_output", "call_id": call.call_id, "output": output}
```

Gemini의 thought signature와 OpenAI의 reasoning 항목 등 다음 요청에 필요한 응답 정보도 이력에 유지합니다. 한 번의 `generate()`는 독립 요청이고, 도구 반복에서는 명시적으로 `history`를 만들어 전달합니다.

도구 스키마는 strict API 형식에 맞춰 변환합니다. 선택 인자도 `required`에 넣되 `null`로 생략을 표현하고, 실제 실행 시 기본값으로 처리합니다.

### 전체 흐름을 제어하는 함수

| 함수 | 필수 인자 | 반환값 |
|---|---|---|
| `run_pipeline(question, settings, reference_date, *, answer_instructions=None)` | 질문, 설정, 기준일 | 답변·의도·도구 기록 `dict` |
| `generate_final_answer(agent, question, intent, trace, *, answer_instructions=None)` | OpenAI 객체, 원문, 의도, 실행 기록 | 최종 답변 `str` |

최종 답변 생성에는 사용자 원문, 의도, 기준일, 실제 도구 호출과 DB 결과를 전달합니다. Gemini가 쓴 중간 설명 문장을 조회 근거로 전달하지 않습니다.

확인한 DB 결과에 근거한 자연어 답변 예시:

```text
E001 김가온의 2026년 11월 법인카드 사용내역은
3건이며, 사용액 합계는 423,500원입니다.
```

이 문장은 실제 모델 응답이 아니라 설명용 예시입니다.

`ToolExecutionIncomplete`는 필요한 조회 근거가 없거나 도구 실행을 완료하지 못했을 때 사용하는 사용자 정의 예외입니다. `ExitStack`은 중간에 실패해도 생성한 클라이언트를 정리하도록 사용합니다.

## 20 테스트의 목적과 문법

```python
class MyTests(unittest.TestCase):
    def test_example(self):
        self.assertEqual(actual, expected)
```

| 문법 | 기능 |
|---|---|
| `assertEqual(actual, expected)` | 두 값 비교 |
| `assertTrue(value)` | 참인지 검사 |
| `assertRaises(Error)` | 지정 예외가 발생하는지 검사 |
| `Mock(return_value=...)` | 가짜 응답 객체·함수 |
| `patch(...)` | 검사 중 특정 함수·환경변수 등을 대체 |
| `TemporaryDirectory()` | 테스트용 임시 DB 폴더 |
| `httpx2.MockTransport` | 실제 모델 API 대신 모의 HTTP 응답 |

```python
with self.assertRaises(ValueError):
    parse_reference_date("2026-11-31")
```

```python
generate = Mock(return_value='{"intent": "card_usage"}')
```

DB 테스트는 실제 임시 SQLite를 사용합니다. 모델 관련 테스트는 가짜 응답으로 요청 형식과 후속 처리를 검사합니다. 모의 테스트 통과가 실제 모델의 모든 자연어 해석 정확성을 보장하지는 않습니다.

## 21 실행 예시

아래 명령은 각각 해당 `main.py`가 있는 폴더에서 실행합니다. 설치는 해당 폴더의 `requirements.txt`를 사용합니다.

### 구조화 출력

```bash
python main.py inspect --row 1
```

첫 세 명령은 모델 API를 호출하지 않습니다. 상품 파일이 없는 상태에서 상품 데이터 모드를 선택하면 다운로드 요청은 발생할 수 있습니다.

### 에이전트 오케스트레이션

```bash
python custom_tools.py --init-db
python main.py --question "E001의 2026년 11월 카드 사용액 합계를 알려줘"

python main.py --test-intents --reference-date 2026-11-22
```

`--analyze-intent`와 `--test-intents`도 실제 Gemini API를 호출합니다. `--json`은 답변뿐 아니라 의도·도구 실행·오류 정보를 출력하는 옵션입니다. DB 생성은 별도 명령이며 모델에 공개된 도구가 아닙니다.

## 22 꼭 기억할 개념

| 개념 | 정의와 기억할 점 |
|---|---|
| 구조화 출력 | 필드와 타입을 정해 결과를 받는 방식 |
| JSON | 데이터를 교환하는 텍스트 형식 |
| JSON Schema | 구조·타입·필수 필드 규칙 |
| Pydantic 모델 | 타입 선언을 바탕으로 데이터를 검증하는 클래스 |
| 타입 힌트 | 기대 타입 표현. 일반 파이썬의 자동 검증 기능은 아님 |
| 필수와 nullable | 키가 필수인지와 값으로 `None`을 허용하는지는 별개 |
| 형식 검증 | 필드·타입·허용값 확인 |
| 업무 규칙 검증 | 원본 값·식별자·기간·실행 조건 확인 |
| 직렬화 | 객체를 저장·전달 가능한 표현으로 변환 |
| 역직렬화 | 문자열 등을 객체로 복원 |
| Tool Calling | 모델이 함수 이름과 인자를 요청하고 프로그램이 실행 |
| 도구 명세와 등록부 | 모델에 보여주는 설명과 실제 실행 함수의 연결은 별개 |
| 오케스트레이션 | 분석·조회·답변 순서와 실패 처리 조율 |
| 파라미터 바인딩 | SQL 문장과 값을 분리하여 전달 |
| 근거 기반 답변 | 실제 조회 결과에서 사실과 숫자를 가져오는 답변 |
| 결과 상한 | `truncated=True`이면 전체 목록으로 취급하면 안 됨 |
| 재현성 | 시드·기준일·입력·기록을 남겨 같은 조건으로 확인 |
| Mock 테스트 | 가짜 응답으로 처리 로직 검사. 실제 모델 평가와 구분 |

자주 쓰는 변환을 연결하면 다음과 같습니다.

```python
json.dumps(data)                     # dict → JSON str
json.loads(text)                     # JSON str → dict/list 등
Contact.model_validate(data)         # dict → Contact
Contact.model_validate_json(text)    # JSON str → Contact
obj.model_dump()                     # Contact → dict
obj.model_dump_json()                # Contact → JSON str
```

두 실습의 공통 원칙은 모델의 출력을 정해진 형식으로 받고, 코드로 검증하고, 실제 데이터와 비교하여 사용하는 것입니다. 형식이 맞는 것과 내용이 맞는 것은 각각 확인해야 합니다.
