# 실행 방법과 오류 해결

## 1. 실행 위치 통일

이 문서의 모든 `python day14/...` 명령은 프로젝트 루트에서 실행합니다.

```bash
cd /Users/imijeong/Downloads/AIO_4_class
conda activate py313
python -m pip install redis python-dotenv
```

`py313`이 이미 만들어져 있다는 전제입니다. VS Code 오른쪽 위 실행 버튼으로 인자 없이 실행하면 argparse가 필수 명령이 없다고 안내할 수 있으니 아래처럼 터미널에서 실행하세요.

루트의 `.env`에는 다음 항목이 필요합니다. 기존 파일의 다른 설정은 유지하고 누락된 항목만 추가합니다.

```env
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
SQLITE_PATH=messages.db
```

`SQLITE_PATH`는 원본 DB 파일의 경로입니다. 이 예에서는 루트에 `messages.db`가 생성됩니다. 상대 경로는 **현재 터미널 폴더** 기준이므로 실행 위치를 바꾸면 다른 DB를 열 수 있습니다. `.env`가 있는 폴더를 자동 기준으로 삼지는 않습니다. 상위 폴더가 없는 경로를 지정하면 SQLite가 폴더까지 자동으로 만들지는 않습니다.

`main2_teacher.py`, `main6.py`, `main7.py`, `main8.py`는 `.env` 상대 경로를 명시하므로 특히 루트 실행이 중요합니다.

## 2. Redis 서버 준비

Mac에서 Docker Desktop을 실행한 상태로 아래를 입력합니다. 미설치라면 [Docker 공식 Mac 설치 안내](https://docs.docker.com/desktop/setup/install/mac-install/)를 참고하세요.

```bash
docker --version
docker ps -a
```

`kdt-redis`가 **없을 때만** 새로 만듭니다.

```bash
docker run -d --name kdt-redis -p 127.0.0.1:6379:6379 redis:7.4 redis-server --save "" --appendonly no
```

| 부분 | 의미 |
|---|---|
| `docker run` | 이미지로 새 컨테이너 생성·실행 |
| `-d` | 백그라운드 실행 |
| `--name kdt-redis` | 컨테이너 이름 |
| `-p 127.0.0.1:6379:6379` | Mac 내부 6379를 컨테이너 6379에 연결 |
| `redis:7.4` | Redis 이미지의 7.4 태그. 로컬에 없으면 다운로드 |
| `redis-server` | 컨테이너 안에서 실행할 프로그램 |
| `--save ""` | Redis의 자동 RDB 스냅샷 저장 비활성화 |
| `--appendonly no` | AOF 변경 기록 비활성화 |

컨테이너가 이미 있고 중지된 상태라면 다음을 씁니다.

```bash
docker start kdt-redis
```

접속 확인:

```bash
docker exec kdt-redis redis-cli PING
```

`PONG`이면 서버가 응답합니다. `docker --version`만 성공한 것은 CLI가 있다는 뜻이지 서버 정상 상태 확인은 아닙니다.

## 3. Docker와 Redis CLI 명령 모음

```bash
docker ps
# 실행 중인 컨테이너

docker ps -a
# 중지된 것을 포함한 전체 컨테이너

docker ps -al
# 가장 최근에 생성한 컨테이너 한 개. 전체 목록 명령은 ps -a

docker exec kdt-redis redis-server --version
# 컨테이너 안의 Redis 프로그램 버전

docker exec -it kdt-redis sh
# 컨테이너의 셸 열기
```

셸은 명령어를 해석하고 실행하는 프로그램입니다. Mac의 `zsh`와 컨테이너 안의 `sh`는 서로 다른 환경입니다. `exec`는 실행 중인 컨테이너 안에서 추가 명령을 실행하고, `-i`는 입력을 열어 두며, `-t`는 터미널을 할당합니다.

셸 대신 Redis 명령 입력 화면을 바로 열려면:

```bash
docker exec -it kdt-redis redis-cli
```

이 화면에서는 Docker 명령 대신 Redis 명령을 입력합니다.

```redis
SET day14:cli:message hello
GET day14:cli:message
TTL day14:cli:message
EXPIRE day14:cli:message 60
DEL day14:cli:message
exit
```

`exit`는 접속한 프로그램만 끝냅니다. Redis 서버는 계속 실행됩니다. 셸에서 Redis CLI를 열었다면 각각 종료해야 Mac 터미널로 돌아옵니다.

Mac 터미널에서 한 번만 Redis 명령을 보내려면 `-it` 없이 실행합니다.

```bash
docker exec kdt-redis redis-cli SET day14:cli:message hello
docker exec kdt-redis redis-cli GET day14:cli:message
docker exec kdt-redis redis-cli TTL day14:cli:message
```

컨테이너 관리:

```bash
docker stop kdt-redis
# 중지. 이 실습 설정에서는 메모리 데이터 소멸

docker start kdt-redis
# 기존 컨테이너 시작

docker restart kdt-redis
# 중지 후 다시 시작
```

컨테이너가 더 필요 없을 때에만 삭제합니다.

```bash
docker stop kdt-redis
docker rm kdt-redis
```

`rm`은 컨테이너 삭제이고 Redis 이미지까지 삭제하지는 않습니다. Mac에 만든 SQLite 파일도 이 컨테이너 삭제와 별개입니다.

## 4. 단계별 실습

### 기본 조작과 자료형

```bash
python day14/main.py
python day14/main2_teacher.py
```

만료 전·후 값과 자료형별 명령의 차이를 확인합니다.

### 세션

```bash
python day14/main3.py create demo-a
```

출력된 세션 ID를 복사해 넣습니다. 아래 `sid_실제발급값`은 예시 자리표시자입니다.

```bash
python day14/main3.py get sid_실제발급값
python day14/main3.py logout sid_실제발급값
python day14/main3.py get sid_실제발급값
```

마지막에는 삭제된 세션이라 거절됩니다. 60초가 지나도 같은 결과입니다.

### 캐시 HIT와 MISS

```bash
python day14/main5.py init
python day14/main5.py evict demo-a
python day14/main5.py history demo-a
python day14/main5.py history demo-a
```

정상적인 순차 실행에서 마지막 두 조회는 MISS → HIT입니다. 60초 뒤 조회하면 다시 MISS가 됩니다. `evict`는 SQLite 원본을 삭제하지 않습니다.

### 최종 대화 프로그램

```bash
python day14/main8.py init
python day14/main8.py create demo-a
```

여기서 출력된 ID를 저장해 사용합니다. 아래 값은 실제 ID로 교체하세요.

```bash
SID='sid_실제발급값'
python day14/main8.py chat "$SID" "내 이름은 민수"
python day14/main8.py chat "$SID" "내 이름이 뭐야?"
python day14/main8.py history "$SID"
python day14/main8.py evict "$SID"
python day14/main8.py history "$SID"
python day14/main8.py logout "$SID"
```

`SID`는 현재 셸에서 세션 ID를 잠시 기억하는 변수이고, Python은 `"$SID"` 자리에 들어간 값을 인자로 받습니다. 캐시를 삭제한 뒤에도 원본이 남아 있어 history를 복원합니다. 로그아웃 후 같은 ID로 조회하면 거절되지만, 새 세션을 발급받으면 사용자 원본 대화는 남아 있습니다.

새 대화를 저장하면 캐시 버전도 바뀌므로 연속된 `chat`에서 매번 HIT가 나올 필요는 없습니다. 같은 버전의 `history`를 반복할 때 HIT를 관찰하기 쉽습니다.

### 장애 정책 비교

Redis가 멈추면 실습 중인 세션·캐시가 사라지므로, 그 영향을 관찰할 때만 다음 순서를 사용합니다.

```bash
python day14/main7.py init
python day14/main7.py create demo-a
docker stop kdt-redis
python day14/main7.py history demo-a
python day14/main7.py session sid_main7에서발급된실제값
docker start kdt-redis
```

`history`는 SQLite를 통해 `BYPASS`로 조회할 수 있고 `session`은 확인 불가로 거절됩니다. 재시작 후에는 세션을 다시 만들어야 합니다. `main8.py`는 모든 대화 요청 앞에 세션 검증이 있으므로 Redis 중단 상태에서 history가 통과하지 않습니다.

## 5. 자주 만나는 오류

| 증상 | 원인과 해결 |
|---|---|
| `zsh: command not found: docker` | Docker CLI 경로를 못 찾음. Docker 설치 확인, VS Code 완전 종료 후 재실행. 계속되면 일반 터미널의 `command -v docker` 결과와 PATH 비교 |
| Docker daemon 연결 실패 | Docker Desktop이 실행 중인지 확인 |
| 컨테이너 이름 충돌 | `docker ps -a`로 기존 것 확인. 새 `run` 대신 `start` |
| 포트 6379 사용 중 | 기존 Redis·컨테이너 확인. 다른 Mac 포트를 쓸 경우 `.env`의 포트도 함께 변경 |
| `python: can't open file .../pip` | `python pip install`이 아니라 `python -m pip install` |
| `ModuleNotFoundError: redis` | 현재 Python 환경에 설치. `conda activate py313` 후 `python -m pip install redis` |
| `ModuleNotFoundError: dotenv` | 설치 이름은 `python-dotenv` |
| 필수 설정 누락 | `.env` 위치, 변수 이름, 비어 있는 값 확인. main5 이후는 `SQLITE_PATH`도 필요 |
| `.env`를 바꿔도 값이 안 바뀜 | 기존 셸 환경변수가 우선일 수 있음. 현재 코드의 `override=False` 동작 확인 |
| 원본 DB 없음·테이블 없음 | 같은 실행 폴더·같은 `SQLITE_PATH`로 해당 파일의 `init` 실행 |
| `unable to open database file` | DB 상위 폴더 존재 여부·권한·경로 확인 |
| 세션 없음·만료 | 같은 파일에서 새 세션 발급, 실제 ID 사용. Redis 재시작·로그아웃 여부 확인 |
| `WRONGTYPE` | 키 자료형에 맞는 명령 사용. Hash는 GET 대신 HGET/HGETALL |
| 이름을 못 찾음 | 정확한 `내 이름은 ...` 형식인지, 최근 여섯 메시지 안에 남아 있는지 확인 |
| `init` 후 예제 내용이 그대로 | 기존 데이터가 있으면 유지하는 코드. init은 전체 초기화·삭제 명령이 아님 |

개별 파일의 명령 목록은 다음처럼 확인합니다.

```bash
python day14/main8.py --help
```
