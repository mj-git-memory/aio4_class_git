## 2. 먼저 기억할 핵심 개념

| 개념 | 쉬운 정의 | 이 실습에서의 의미 |
|---|---|---|
| 함수 | 이름을 붙여 여러 번 호출할 수 있게 묶은 코드 | 연결 생성, 입력 조합, 답변 수신을 나눈다. |
| 매개변수 | 함수가 받을 값에 붙인 이름 | `def read_information(s):`의 `s` |
| 인자 | 함수를 호출할 때 실제로 전달한 값 | `read_information(students)`의 `students` |
| 객체와 참조 | 데이터가 객체이고, 변수는 그 객체를 가리키는 이름 | `score`와 원본 학생의 점수가 같은 딕셔너리를 가리킬 수 있다. |
| 상태 | 현재 상황을 나타내는 데이터 | 질문 처리 중인지, 실패했는지, 완료됐는지 |
| 세션 상태 | 사용자 세션의 재실행 사이에 유지하는 값 | `st.session_state`에 대화와 pending 저장 |
| 스트리밍 | 결과를 완성 전에 조각 단위로 전달받는 방식 | `stream=True`로 이벤트를 차례로 수신 |
| 이벤트 | 처리 중 발생한 일을 나타내는 알림 데이터 | 텍스트 도착, 완료, 실패 |
| pending | 아직 성공 처리하지 않은 작업을 보관하는 값 | 실패한 질문을 재시도하거나 취소할 때까지 보관 |
| 생성기 | 필요할 때 다음 값을 하나씩 만들어 주는 객체 | `yield`로 텍스트 조각을 전달 |
| 버퍼 | 바로 처리하지 않고 임시로 모아두는 공간 | 짧은 텍스트 조각 여러 개를 모아 화면을 갱신 |
| 예외 | 정상 진행이 어려운 상황을 알리는 신호 | API 오류나 강제 중단을 처리 |

특히 다음 여섯 문장을 기억한다.

1. `return`은 값을 전달하며, 함수 안의 변수 이름을 함수 밖에 만들어 주지는 않는다.
2. `students.copy()`는 바깥 리스트만 복사한다. 안의 딕셔너리는 공유한다.
3. 첫 텍스트를 받았다고 답변이 완성된 것은 아니다.
4. Streamlit 재실행 때 유지할 값은 `st.session_state`에 저장한다.
5. 정상 완료된 질문·답변만 성공 기록에 넣는다.
6. 텍스트를 묶어 표시하더라도 공백·줄바꿈·마지막 남은 조각은 보존해야 한다.

## 3. Python 문법 읽기

### 3.1 리스트와 딕셔너리

`list`는 순서대로 값을 담고, `dict`는 키와 값의 쌍을 담는다.

```python
students = [
    {
        'student_num': '001',
        'info': {
            'name': '홍길동',
            'score': {'kor': 100},
        },
    },
]

print(students[0]['info']['score']['kor'])  # 100
```

왼쪽부터 읽으면 다음과 같다.

| 표현 | 가리키는 값 |
|---|---|
| `students` | 학생 목록 |
| `students[0]` | 첫 번째 학생 딕셔너리. 인덱스는 0부터 시작 |
| `students[0]['info']` | 첫 학생의 정보 딕셔너리 |
| `students[0]['info']['score']` | 첫 학생의 점수 딕셔너리 |
| `students[0]['info']['score']['kor']` | 국어 점수 정수 |

같은 딕셔너리 안에 동일한 키를 두 번 쓰면 나중 값이 남는다.

```python
student = {'name': '홍길동', 'name': '이순신'}
print(student)  # {'name': '이순신'}
```

두 학생을 저장하려면 `[학생1딕셔너리, 학생2딕셔너리]`처럼 분리한다.

### 3.2 함수 정의·호출·반환

```python
def add_score(score, amount=50):
    # score, amount는 매개변수. amount의 기본값은 50.
    return score + amount

result = add_score(100)             # 위치 인자로 전달: 150
other = add_score(score=100, amount=20)  # 키워드 인자로 전달: 120
print(result, other)
```

- `def`: 함수 정의
- `함수이름(...)`: 함수 호출
- `return 값`: 값을 돌려주고 일반 함수 실행을 끝냄
- 반환값을 변수에 저장하지 않으면 나중에 그 변수로 사용할 수 없음
- `return`이 없거나 `return`만 실행되면 반환값은 `None`

실습의 `main()`은 화면을 구성하고, `create_client()`는 API 클라이언트를 반환한다.

### 3.4 리스트·딕셔너리 메서드와 컴프리헨션

```python
messages = []
messages.append({'role': 'user', 'content': '질문'})  # 항목 하나 추가
messages.extend([
    {'role': 'assistant', 'content': '답변'},
    {'role': 'user', 'content': '다음 질문'},
])  # 목록의 각 항목을 추가

stats = {'first': None}
stats.update(first=0.2, total=1.5)  # 여러 키를 갱신
print(stats.get('partial', ''))    # 키가 없으면 기본값 ''
```

`append([a, b])`는 목록 하나를 넣고, `extend([a, b])`는 두 항목을 넣는다.

컴프리헨션은 기존 데이터를 순회하여 새 리스트나 딕셔너리를 만드는 문법이다.

```python
messages = [{'role': 'assistant', 'content': '답변', 'elapsed': 1.2}]

history = [
    {'role': item['role'], 'content': item['content']}
    for item in messages
]
# 화면용 elapsed를 빼고 API가 받는 대화 데이터만 만든다.

stats = {'first': 0.2, 'total': 1.5, 'partial': '답변'}
saved_stats = {
    key: value
    for key, value in stats.items()
    if key != 'partial'
}
```

`items()`는 키와 값을 함께 순회한다. 위 `history`는 새로운 목록과 딕셔너리를 만들지만, 모든 내부 값을 깊은 복사하는 문법은 아니다.

### 3.5 빈 값 검사와 문자열

```python
question = '   '
if not question or not question.strip():
    print('질문을 입력해주세요.')
```

`None`, `''`, `[]`, `{}`, `0`은 조건식에서 거짓으로 취급된다. `strip()`은 양 끝의 공백·줄바꿈을 제거한 **새 문자열**을 반환한다.

질문의 불필요한 앞뒤 공백을 지울 때는 유용하지만, 모델의 텍스트 조각마다 `strip()`을 호출하면 필요한 띄어쓰기와 줄바꿈이 사라질 수 있다.

## 4. 지역 변수·참조·얕은 복사·깊은 복사

### 4.1 지역 변수와 반환값

```python
def read_information(s):
    score = s[0]['info']['score']
    score['kor'] += 50
    return score

# students가 위 학생 목록이라고 가정
scores = read_information(students)
print(scores)
```

`score`는 함수 안에서 만든 지역 변수다. `scores`는 함수 밖에서 반환값을 받은 별개의 이름이다. 두 이름이 같을 필요는 없다.

```python
result = read_information(students)
print(result)
# 또는: print(read_information(students))
```

함수 밖에서 정의하지 않은 `score`를 출력하면 `NameError`가 발생한다. 다만 반환값을 저장하지 않았어도, 함수 안에서 원본 딕셔너리를 수정한 효과는 남는다.

### 4.2 대입은 자동 복사가 아니다

```python
original = {'kor': 100}
score = original
score['kor'] += 50
print(original)  # {'kor': 150}
```

`score = original`은 같은 딕셔너리에 이름을 하나 더 붙이는 것이다.

반대로 다음 대입은 `score`라는 이름이 가리키는 대상을 바꾼다.

```python
original = {'kor': 100}
score = original
score = {'kor': 0}
print(original)  # {'kor': 100}
```

**딕셔너리 안의 값을 수정하는 것**과 **변수에 다른 객체를 대입하는 것**은 다르다.

이 원리 때문에 `main4.py`의 `pending['state'] = 'failed'`는 세션에 보관한 딕셔너리에도 반영된다. `stats.update(...)`도 호출한 쪽에서 같은 사전으로 확인할 수 있다.

### 4.3 얕은 복사: 바깥 목록만 새로 생성

```python
students = [{'info': {'score': {'kor': 100}}}]
copied = students.copy()

print(copied is students)        # False: 바깥 목록은 다름
print(copied[0] is students[0])  # True: 내부 학생 딕셔너리는 같음

copied[0]['info']['score']['kor'] = 50
print(students[0]['info']['score']['kor'])  # 50
```

`is`는 같은 객체인지, `==`는 값이 같은지 비교한다.

```text
원본 목록   ──┐
              ├──→ 같은 학생 정보 딕셔너리 → 같은 점수 딕셔너리
복사한 목록 ──┘
```

복사한 **목록 자체**에 항목을 추가하면 원본 목록의 길이는 바뀌지 않는다.

```python
copied.append({'info': {'name': '새 학생'}})
print(len(copied))    # 2: 위의 학생 1명 예제 기준
print(len(students))  # 1
```

### 4.4 깊은 복사: 내부 데이터도 따로 복사

```python
from copy import deepcopy

students = [{'info': {'score': {'kor': 100}}}]
copied = deepcopy(students)
copied[0]['info']['score']['kor'] = 50

print(copied[0]['info']['score']['kor'])    # 50
print(students[0]['info']['score']['kor'])  # 100
```

이 실습처럼 리스트와 딕셔너리가 중첩된 데이터에서 원본을 유지하며 수정하려면 `deepcopy()`를 사용한다. 모든 경우에 무조건 깊은 복사가 필요한 것은 아니다. 원본 상태를 의도적으로 갱신하는 세션 코드에서는 공유 참조가 필요하다. 정의는 [Python 공식 copy 문서](https://docs.python.org/3/library/copy.html)와 일치한다.

### 4.5 현재 deep_not.py의 실행 순서

| 실행 | 반환된 국어 점수 | 원본 국어 점수 |
|---|---:|---:|
| 시작 | — | 100 |
| `read_information(students.copy())` | 150 | 150 |
| `read_information(students)` | 200 | 200 |
| `read_information(deepcopy(students))` | 250 | 200 |
| `copied[0]['info']['score']['kor'] = 50` | — | 50 |

추가로 기억할 점:

- `scores1`과 `scores2`는 같은 원본 점수 딕셔너리를 가리킨다. `scores1`이 출력 당시 150이었다고 해서 150이 고정 저장된 것은 아니다.
- 나중에 원본을 수정한 뒤 `scores1`을 다시 출력하면 바뀐 점수가 보인다.
- 현재 파일은 학생이 **두 명**이다. 맨 아래 `append` 후 `len(copied)`는 **3**, `len(students)`는 **2**다. 파일의 `# 2`, `# 1` 주석은 실제 학생 수와 맞지 않는다.
- `scores = s[0]['info']['score']['kor'] = 50`처럼 쓰면 `scores`에는 사전이 아닌 정수 50이 들어간다. 따라서 `scores['kor']`는 `TypeError`다.

## 5. 환경 변수와 API 호출

### 5.1 모듈·패키지·클라이언트 구분

- **모듈**: 가져와 쓸 수 있는 Python 코드 단위. 예: `os`, `time`.
- **패키지**: 여러 모듈을 묶어 제공하는 단위. 예: `streamlit`, `openai`.
- **클라이언트 객체**: 서버에 요청을 보내는 데 사용하는 객체. 예: `OpenAI(...)`가 만든 값.

| 구분 | 사용하는 것 | 별도 설치 |
|---|---|---|
| Python 표준 라이브러리 | `os`, `time`, `copy`, `concurrent.futures` | 필요 없음 |
| 외부 패키지 | `streamlit`, `python-dotenv`, `openai` | 필요 |
| 설치 이름과 import 이름 차이 | `python-dotenv` → `from dotenv import load_dotenv` | 구분해서 기억 |

### 5.2 .env 읽기

```python
import os
from dotenv import load_dotenv

load_dotenv()
key = os.getenv('GROQ_API_KEY', '').strip()
if not key:
    raise ValueError('GROQ_API_KEY를 설정해주세요.')
```

- `load_dotenv()`: .env 파일의 설정을 환경 변수로 읽는다.
- `os.getenv('이름', 기본값)`: 환경 변수 조회.
- `raise ValueError(...)`: 설정값이 잘못된 상황을 예외로 알림.
- 기본 `load_dotenv()`는 이미 존재하는 환경 변수를 덮어쓰지 않는다.

키 원문을 코드나 학습 문서에 넣지 않고, .env가 버전 관리에 올라가지 않도록 .gitignore에서 제외한다.

### 5.3 Groq 연결

실습은 OpenAI Python SDK의 인터페이스를 이용하되, 요청 서버는 `base_url`에 지정한 **Groq**다.

```python
from openai import OpenAI

client = OpenAI(
    api_key=key,
    base_url='https://api.groq.com/openai/v1',
    timeout=60.0,
    max_retries=0,

```

| 인자 | 용도 |
|---|---|
| `api_key` | 인증에 사용할 키 |
| `base_url` | 요청을 보낼 API 서버 주소 |
| `timeout` | 네트워크 작업의 대기 제한. 앱 요청 전체가 무조건 이 시간 안에 끝난다는 뜻은 아님 |
| `max_retries=0` | SDK의 자동 재시도를 끔. 사용자 버튼에 의한 재시도와 구분 |

### 5.4 대화 메시지 조합과 프롬프트

```python
system_message = {'role': 'system', 'content': '친절한 요리 도우미입니다.'}
history = [
    {'role': 'user', 'content': '두부 요리 추천해줘'},
    {'role': 'assistant', 'content': '두부조림을 추천합니다.'},
]
question = '2인분 재료는?'

inputs = [system_message] + history + [
    {'role': 'user', 'content': question},
]
```

- `system`: 역할·답변 원칙·형식 등의 지침.
- `user`: 사용자의 질문.
- `assistant`: 이전 AI 답변.
- `history`: 이전 대화 기록. 다음 요청에 직접 전달해야 문맥을 제공할 수 있다.

소스의 요리 프롬프트는 역할, 재료·분량·시간·순서, 식품 안전, 언어와 범위를 지정한다. 프롬프트를 작성했다고 외부 검색 기능이 생기지는 않는다. 이 폴더의 앱에는 별도의 웹 검색 도구가 연결되어 있지 않다.

### 5.5 두 API 형식을 섞지 않기

```python
# main1.py: 완성된 응답을 한 번에 받음
response = client.chat.completions.create(
```

`messages=`와 `input=`, 응답 본문과 이벤트 처리 방식을 구분한다. 정확한 속성 이름은 `client.responses`다.

## 6. Streamlit 화면과 세션

### 6.1 재실행과 session_state

Streamlit은 위젯 상호작용에 따라 스크립트를 다시 실행한다. 일반 변수만으로 대화를 매번 초기화하면 이전 기록이 사라진다.

```python
import streamlit as st

if 'messages' not in st.session_state:
    st.session_state.messages = []

question = st.chat_input('질문을 입력하세요')
if question:
    st.session_state.messages.append(
        {'role': 'user', 'content': question}
    )

for message in st.session_state.messages:
    with st.chat_message(message['role']):
        st.markdown(message['content'])
```

위 코드는 세션의 동작을 보여주는 작은 예제다. `main4~5.py`는 미완성 질문을 성공 기록에 바로 넣지 않고 pending에 보관한다.

세션 상태는 사용자 세션의 재실행 사이에 값을 유지한다. 브라우저 새로고침 등으로 연결이 재생성되면 초기화될 수 있으므로 영구 저장소로 생각하지 않는다. [Streamlit 공식 Session State 문서](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state)

### 6.2 화면을 만들 때 사용하는 것

| 기능 | 코드 | 뜻 |
|---|---|---|
| 페이지 설정 | `st.set_page_config(page_title='요리 AI')` | 제목 등 설정 |
| 제목 | `st.title('요리 AI')` | 큰 제목 |
| 보조 설명 | `st.caption('설명')` | 작은 설명 |
| 질문 입력 | `st.chat_input('질문')` | 채팅 입력창 |
| 말풍선 | `with st.chat_message('assistant'):` | 해당 역할의 메시지 영역 |
| Markdown 표시 | `st.markdown(answer)` | 제목·목록·표 등을 표시 |
| 임시 대기 안내 | `with st.spinner('생성 중...'):` | 작업 중 안내 |
| 재사용할 출력 자리 | `box = st.empty()` | 나중에 같은 위치 갱신 |
| 진행 상태 | `st.status(...)` | 요청·수신·완료·오류 안내 |
| 읽기 영역 | `with st.container(height=400, border=True):` | 높이를 고정하고 내부 스크롤 사용 |
| 접는 영역 | `with st.expander('상세'):` | 사용자가 상세 내용 열기 |
| 선택 | `st.sidebar.selectbox('표시', ['접기', '펼치기'])` | 사이드바 선택 |
| 숫자 | `st.sidebar.number_input('초', value=5.0)` | 숫자 입력 |
| 범위 조절 | `st.sidebar.slider('높이', 200, 500, 400)` | 슬라이더 |
| 버튼 | `st.button('재시도')` | 눌린 실행에서 참 |
| 입력 비활성화 | `st.chat_input('질문', disabled=True)` | 새 질문 차단 |
| 강제 재실행 | `st.rerun()` | 현재 실행을 멈추고 다시 실행 |

`st.empty()`는 출력할 **자리 하나**다. `box.markdown('새 내용')`을 다시 호출하면 그 자리의 내용을 바꾸므로 새 글을 계속 아래에 추가하는 것과 다르다.

`with`는 문맥을 관리하는 Python 문법이다. Streamlit에서는 어느 컨테이너에 내용을 넣을지 지정하고, `with create_client() as client:`에서는 API 연결 자원 정리를 돕는다.

## 7. 스트리밍·시간 측정·상태 안내

### 7.1 수신 이벤트

`main2~5.py`는 스트림을 순회하며 다음 이벤트를 구분한다.

| 이벤트 | 처리 |
|---|---|
| `response.output_text.delta` | `event.delta`의 새 텍스트를 누적 |
| `response.completed` | 완료 이벤트를 확인하고 수신 종료 |
| `response.failed` / `response.incomplete` / `error` | 예외로 실패 처리 |

수신 조각 하나가 반드시 글자 하나, 단어 하나 또는 토큰 하나인 것은 아니다. 상태 알림만 들어오거나 빈 텍스트가 들어올 수도 있다. [OpenAI Docs 스트리밍 안내](https://developers.openai.com/api/docs/guides/streaming-responses)

### 7.2 세 가지 시간 구분

```text
요청 시작 ── 첫 텍스트 수신 ── 첫 화면 표시 ── 정상 완료
```

| 값 | 측정 대상 |
|---|---|
| `first` | 요청 시작부터 첫 번째 비어 있지 않은 답변 텍스트 수신까지 |
| `first_display` | main5에서 첫 Markdown 갱신 함수를 호출한 뒤까지 |
| `total` | 해당 요청 시작부터 완료 이벤트 확인까지. 실패 시 종료까지 기록하기도 함 |

`first_display`는 Python 서버 쪽 측정값이다. 실제 브라우저가 화면을 그린 정확한 시각을 측정하는 것은 아니다.

```python
import time

started = time.perf_counter()
# 측정할 작업 수행
elapsed = time.perf_counter() - started
print(f'{elapsed:.2f}초')
```

`perf_counter()`는 짧은 경과 시간을 측정할 때 쓰는 시계다. 두 시점에서 같은 시작값을 빼야 비교할 수 있다. `main1.py`는 사용자 입력 처리 이후부터, `main2~5.py`는 수신 함수 안의 요청 직전부터 시간을 재므로 측정 범위가 완전히 같지는 않다.

스트리밍을 켠다고 모델의 전체 생성 시간이 반드시 줄어드는 것은 아니다. 완성되기 전에 읽기 시작할 수 있다는 점이 핵심이다.

### 7.3 st.status의 label과 state

```python
status = st.status('요청 중', state='running', expanded=True)
# 첫 텍스트 도착
status.update(label='수신 중', state='running', expanded=True)
# 정상 완료 및 답변 검증 후
status.update(label='완료', state='complete', expanded=False)
```

- `label`: 사람이 읽는 문구.
- `state`: `running`, `complete`, `error` 중 하나.
- `expanded`: 상세 내용을 펼칠지 여부.

`state='수신 중'`으로 쓰는 것이 아니다. 요청 중과 수신 중 모두 `running` 상태이며 문구를 바꾼다.

### 7.4 main2.py의 스레드와 Future

```python
from concurrent.futures import ThreadPoolExecutor, TimeoutError as FutureTimeoutError

def work():
    return '완성된 답변'

with ThreadPoolExecutor(max_workers=1) as executor:
    future = executor.submit(work)
    try:
        answer = future.result(timeout=5.0)
    except FutureTimeoutError:
        print('5초 이상 걸립니다. 계속 기다립니다.')
        answer = future.result()
```

- `submit(함수, 인자...)`: 작업을 스레드에 맡기고 Future를 받는다.
- **Future**: 나중에 끝날 작업의 결과를 확인하는 객체.
- `result(timeout=...)`: 지정 시간까지 결과를 기다린다.
- 기다리는 시간이 초과되어도 작업 자체가 취소되는 것은 아니다.
- 두 번째 `future.result()`는 **같은 요청**의 완료를 기다린다. 새 API 요청이 아니다.
- 이 구현에서 Streamlit 화면 함수는 메인 실행에서 호출한다.

## 8. pending·실패·재시도·취소

### 8.1 데이터와 흐름

`pending`은 Python 예약어가 아니다. 미완성 질문을 담기 위해 정한 딕셔너리 키다.

```python
state = {
    'messages': [],  # 완료된 질문·답변만 저장
    'pending': {
        'question': '두부 요리 알려줘',
        'state': 'ready',
        'attempts': 0,
        'stats': {},
        'error': '',
    },
    'fail_next': False,
    'notice': '',
}
```

```text
질문 제출 → pending.ready → running
                            ├─ 정상 완료 → 질문·답변 한 쌍을 messages에 저장
                            │              pending = None
                            └─ 실패 → pending.failed 유지
                                      ├─ 재시도 → ready → 새 요청
                                      └─ 취소 → pending = None
```

이 `ready/running/failed`는 앱 데이터의 상태다. `st.status`의 `running/complete/error`와 혼동하지 않는다.

### 8.2 핵심 함수

| 함수 | 하는 일 |
|---|---|
| `run_pending()` | 보관한 질문을 실행하고 성공 또는 실패로 처리 |
| `commit_success()` | 완료 검증 후 질문과 답변을 성공 기록에 함께 반영 |
| `cancel_pending()` | 미완성 질문·부분 답변과 실패 예약을 비움 |
| `SimulatedDisconnect` | 첫 텍스트 조각 뒤 강제 실패를 나타내는 사용자 정의 예외 |

재시도 시에는 같은 질문으로 **새 API 요청**을 보내며, 이전 부분 답변에 이어 붙이지 않는다. API에 전달하는 history는 성공 기록에서만 만든다.

취소 버튼은 실패 후 보관된 pending을 버리는 기능이다. 이미 네트워크에서 실행 중인 요청을 즉시 중단하는 실시간 취소 기능은 아니다.

강제 실패 버튼도 가짜 텍스트만 보여주는 기능이 아니다. 실제 API에서 첫 조각을 받은 뒤 예외를 발생시키는 실습이다. 첫 조각 수신 전 API 오류가 나면 실패 예약은 남는다.

### 8.3 예외 처리 문법

```python
try:
    value = int('숫자가 아님')
except ValueError as error:
    print('실패:', error)
else:
    print('성공:', value)
finally:
    print('성공/실패와 관계없이 정리')
```

- `try`: 실패할 수 있는 작업.
- `except`: 해당 예외가 발생했을 때 실행.
- `else`: try 블록에서 예외가 없었을 때 실행.
- `finally`: 성공·실패·종료 시 정리할 작업.
- `raise`: 예외를 발생시키거나 처리 중인 예외를 다시 전달.

```python
class SimulatedDisconnect(RuntimeError):
    pass

# raise SimulatedDisconnect('첫 조각 이후 중단')
```

`class ...(...):`는 기존 클래스를 상속해 새 클래스를 정의하는 문법이다. `pass`는 추가 동작 없이 빈 본문을 채운다.

## 9. 생성기와 묶음 갱신

### 9.1 return과 yield

```python
def make_chunks():
    yield '두부'
    yield '\n'
    yield '달걀'

chunks = make_chunks()  # 생성기 객체를 만듦
for chunk in chunks:    # 순회할 때 함수가 진행됨
    print(repr(chunk))
```

`yield`는 값을 하나 전달하고 그 자리에서 잠시 멈춘다. 다음 값을 요청하면 이어서 실행한다. 모든 텍스트를 미리 만든 리스트와 다르다.

생성기는 보통 한 번 순회하면 소진된다. `list(chunks)`로 확인한 뒤 같은 `chunks`를 화면 출력에 다시 쓰면 값이 남지 않을 수 있다.

### 9.2 main5.py의 처리 단계

```text
API 이벤트
   ↓ stream_text(): 실제 텍스트 조각 전달
   ↓ batch_text(): 여러 조각을 묶어 전달
   ↓ render_answer(): 누적 문자열로 Markdown 갱신
   ↓ 완료 검증 후 commit_success()
```

기본 기준은 다음과 같다.

| 설정 | 기본값 | 이유 |
|---|---:|---|
| 첫 조각 | 즉시 표시 | 첫 응답을 오래 기다리지 않도록 |
| `min_chars` | 80자 | 이후 작은 조각들을 묶기 |
| `max_wait` | 0.15초 | 조각이 들어올 때 긴 대기를 줄이는 기준 |
| `reading_height` | 400px | 긴 답변을 내부 스크롤로 읽기 |

실제 조건은 다음과 같다.

```python
if first or size >= min_chars or now - last_flush >= max_wait:
    yield ''.join(buffer)
```

세 조건 중 하나만 충족해도 전달한다. 크기 기준은 정확히 80자씩 자른다는 뜻이 아니다. 새 조각을 더한 누적 길이가 기준 이상이면 그 묶음을 전달한다.

시간 기준은 **다음 조각이 도착할 때 확인**한다. 서버가 아무 데이터도 보내지 않으면 정확히 150ms마다 깨어나는 타이머가 아니다. 인위적인 `sleep`도 사용하지 않는다.

### 9.3 줄바꿈과 마지막 조각 보존

```python
buffer = ['재료', '\n', '- 두부', '\n', '- 달걀']
text = ''.join(buffer)
print(text)
```

`''.join(...)`은 조각들을 그대로 연결한다. `' '.join(...)`은 조각 사이에 새 공백을 넣으므로 이 용도와 다르다.

마지막 버퍼가 기준보다 짧아도 반드시 출력해야 한다.

```python
if buffer:
    yield ''.join(buffer)
```

`main5.py`는 오류 직전 버퍼도 전달한 다음 예외를 다시 발생시킨다. 덕분에 부분 답변은 보이지만 성공 기록에는 들어가지 않는다. `finally`의 `chunks.close()`는 생성기를 닫아 API 스트림 정리를 돕는다.

### 9.4 화면 갱신 횟수와 읽기 영역

```python
with st.container(height=400, border=True):
    answer_box = st.empty()

displayed = ''
# batches는 batch_text(...)가 만든 생성기라고 가정
for batch in batches:
    displayed += batch
    answer_box.markdown(displayed)
```

수신 조각이 100개여도 묶어서 표시하면 화면 갱신은 그보다 적어질 수 있다. 단, 조각이 크거나 도착 간격이 길면 매번 조건을 충족할 수 있으므로 언제나 줄어든다고 단정하지 않는다.

고정 높이는 긴 답변 때문에 페이지 전체가 계속 늘어나는 것을 줄인다. 묶음 갱신은 Markdown 재해석 횟수를 줄이지만, 목록이나 표의 모양 변경을 완전히 없애는 것은 아니다.

`main5.py`는 `st.write_stream()` 대신 생성기를 직접 순회하며 묶음당 한 번 `markdown()`을 호출한다. 어떤 기능을 썼는지는 실제 코드를 기준으로 구분한다.

실행 시작점의 의미:

```python
if __name__ == '__main__':
    main()
```

해당 파일을 직접 실행할 때 `main()`을 호출한다. 다른 파일에서 import할 때 이 블록의 `main()` 호출은 실행되지 않는다. 블록 밖의 최상위 코드는 import 시에도 실행될 수 있다.

### 자주 틀리는 표기

| 잘못된 표기·생각 | 올바른 표기·개념 |
|---|---|
| `time.pref_counter()` | `time.perf_counter()` |
| `max_retires` | `max_retries` |
| `client.response.create()` | `client.responses.create()` |
| `import as streamlit as st` | `import streamlit as st` |
| `return score`면 함수 밖에도 score가 생김 | 반환값을 `result = 함수(...)`로 받아야 함 |
| `copy()`면 내부 데이터도 전부 독립 | 중첩 데이터는 공유할 수 있음 |
| 글자가 보이면 성공 기록에 저장 | 완료 이벤트와 답변 검증 후 저장 |
| `Future.result(timeout=5)`가 요청을 취소 | 기다리기만 중단하고 작업은 계속될 수 있음 |
| `max_wait=0.15`면 항상 150ms 이내 갱신 | 새 조각이 도착할 때만 시간 기준 확인 |
| `st.session_state`가 DB 저장 | 세션의 재실행 사이에 값 유지 |
